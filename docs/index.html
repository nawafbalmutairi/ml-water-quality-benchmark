Comparing Machine Learning Models
for Water Quality Prediction.

I prepared Environment Agency monitoring data in Python and benchmarked four regression models across five water-quality targets, using IBM SPSS Modeler in the modelling workflow and Power BI to present the results.

The project.

Which model works best depends on what it is predicting. This study holds the inputs, chronological split and evaluation metrics consistent within each target to compare four model families fairly.

The study uses observations from 2000–2025 across 14 Environment Agency areas in England. The five targets are Nitrate as N, BOD : 5 Day ATU, Temperature of Water, Oxygen, Dissolved as O2, and pH.

Methodology · Results · Interpretation · Limitations

Methodology.

Preserve temporal order

Training uses 2000–2017; testing uses 2018–2025. This measures performance on later observations. The models use other water measurements from each observation, so this is not a lag-only forecast.

Use measurements and calendar features

Each target is predicted from the other four selected water-quality parameters plus year, month and day. Each target retains its own valid records; sample counts differ across targets.

Respect detection limits

Values marked < or > are treated as missing rather than exact numbers. Data is filtered to five parameters and reshaped from long to wide before modelling.

Keep a baseline

Ridge provides a regularised linear reference against Random Forest, MLP and XGBoost. More complexity must be justified by the measured results.

What the results mean.

Strongest result

XGBoost reaches R² 0.785 on water temperature and leads on four of the five targets. Random Forest also performs well on temperature at 0.729.

An informative failure

All four BOD R² scores are negative. Ridge has the highest BOD R² at −0.007, while XGBoost has the lowest BOD MAE. Different metrics reveal different aspects of error.

Data preparation needed care

I renamed the files manually and spotted my own mistake: the Thames 2000 and 2001 filenames were swapped. I corrected them before constructing the final dataset.

Random Forest also exceeds R² 0.7 on temperature, with 0.729. Weak BOD and nitrate results show the limits of this feature set and setup; they do not prove that those parameters are inherently unpredictable.

The submitted work presents results in a report and an interactive Power BI dashboard. Older dashboard screenshots with totals repeated across four models are omitted here to avoid confusing them with the report’s target-level sample counts.

Limits and next steps.

The inputs exclude site and area context, rainfall, river flow, land use and discharge. Future work could add these variables, tune models per target and use further time-preserving evaluation. These are recommendations, not completed improvements.

The chronological holdout measures performance on later observations using the available water measurements and calendar features. It is not evidence of past-only forecasting. Targets have different valid sample counts, and extensive model-specific tuning was outside the benchmark’s focus.
